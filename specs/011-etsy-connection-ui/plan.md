## UI and state design

Observed public reference in managed Chromium before source edits: light paper rgb(249,246,240), system sans body, ink outlines, asymmetric rounded panels, peach buttons, offset shadows; desktop sidebar and spacious content. Reference390 document width845 is an upstream overflow defect, not fidelity target. Existing003/004 supply Geist and tokens `--paper #f9f6f0`, `--ink #111827`, `--accent #eacdc2`, wash and muted text. Preserve their24/32px spacing,44px targets and inherited sketch radii. Use scoped feature CSS, no new global styling or fonts.

Layout: preview banner → compact sample-scenario selector → connection panel (status and shop details/actions) → invitation-history table. One primary create-invitation action. Supporting copy explains recipient consent and integration-later boundaries. Narrow layouts stack details/actions; only the table region can scroll. No decorative metrics/chart.

Canonical types come from `apps/web/src/lib/api/generated.ts`, reconciled with010 spec/contract. `active` displays Connected (sample); `verification_pending` Pending; `refresh_unknown` Unknown; `reconnect_required` Reconnect required. Empty uses `unconnected`; local disconnect uses `disconnected` and never claims provider revocation. Loading/failure are separate UI states, not fabricated connection enums. Sample shop observation is a separate generated projection, never invented fields on connection status.

Reducer owns transient invitation/history/connection/observation transitions. Creation validates a positive int64 decimal string and preserves all digits; existing pending work prevents duplicates. Confirmation actions carry their target; no timer/poll/network. Scenarios are explicit preview controls, not implicit consent. Native dialog provides modal focus/Escape, explicit close/return focus and a keyboard focus loop. Copy handles rejected clipboard permission and only writes a constant nonfunctional sentence. No browser storage.
