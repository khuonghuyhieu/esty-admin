## Navigation performance source and browser assessment — 2026-11-17

At base c6d7a17, server.ts calls currentAppMe before the RSC page response. ProtectedRoute then calls admitRoute→revalidate; the locked client path awaits auth/context then app/me. Sidebar beginRoute immediately sets routePending; ProtectedRoute substitutes a plain paragraph for the whole page. Sidebar prefetch is disabled. SessionContext combines view/actions into a newly allocated value. Request duplication and placeholder collapse are source findings; excessive React commits are not yet measured. Fonts are local next/font assets using swap; do not attribute the owner's CLS to fonts without shift-source evidence.

Root's existing anonymous Chromium report is `.openai/reports/fe-performance-audit/anonymous-browser-report.json` (local untracked evidence, not a portable setup prerequisite). One unthrottled sample per route/viewport, fresh profile per viewport, five seconds after load: login1440 CLS0.003095/LCP1128ms, login390 CLS0.015286/LCP1016ms. Anonymous application access redirected to login; these are NOT protected-page measurements. Login shift sources include the centered login wrapper/form when session-status height changes. No long tasks or horizontal overflow were recorded in those samples. Owner screenshot CLS0.60 has two shifts but no trace identifying their elements or route; exact cause remains unproved.

Decision: first preserve layout geometry and measure the signed-in journey; then consolidate duplicated admission reads. Prefer one existing current BFF admission operation per navigation plus the existing cookie/generation protocol, not globally caching authorization. Context and me GETs do not mutate the session and may overlap within the existing auth lock if both results are bound to the same valid lifecycle/generation; refresh remains serialized and only follows actual401. No new combined endpoint is selected. Server-rendered private reads must retain their own authorization. The existing sample route bodies contain no user-private business dataset; this permits separating static route delivery from current client admission in the bounded design, subject to route-by-route proof before removing a server membership lookup.

References checked during the audit: [CLS definition and thresholds](https://web.dev/articles/cls), [Next layout persistence](https://nextjs.org/docs/app/getting-started/layouts-and-pages), [authorization near data access](https://nextjs.org/docs/app/guides/authentication), and [Vercel interface guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). A stable layout is not an access control; hiding a DOM node alone is not permission to serialize private data.
